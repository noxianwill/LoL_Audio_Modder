# League Audio Modder (LAM)

[![Python Version](https://img.shields.io/badge/python-3.10%2B-blue.svg)](https://www.python.org/)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![Audio Engine](https://img.shields.io/badge/wwise-v145%20%7C%20v140-orange.svg)](https://www.audiokinetic.com/products/wwise/)
[![Game](https://img.shields.io/badge/game-League%20of%20Legends-C89B3C.svg)](https://www.leagueoflegends.com/)

**League Audio Modder (LAM)** is a professional-grade Wwise audio reconstruction, editing, and modding suite tailored specifically for **League of Legends** asset files. 

It provides an interactive, dark-themed GUI and a high-performance binary processing engine capable of decoding, modifying, rebuilding, and exporting `.bnk` soundbanks, `.wpk` audio packages, and `.wem` audio streams with bit-accurate round-trip fidelity. Additionally, LAM can deconstruct compiled game audio hierarchies back into native **Audiokinetic Wwise authoring projects** (`.wproj`).

## Key Features

- **Full Wwise & Riot Container Support**: Native binary parsing and deterministic rebuilding of `.bnk` (SoundBank), `.wpk` (r3d2 audio package), and `map.bin` (PROP string dictionary) files.
- **Deep Hierarchy Reconstruction**: Reconstructs complete logical audio graphs from raw binary HIRC data:
  ```text
  Event ➔ Action ➔ Container / Blend / Music Track ➔ Sound Object ➔ WEM
  ```
- **Interactive Audio Previewer**: Real-time decoding of proprietary game `.wem` audio files via bundled `vgmstream` integration, playable instantly using `pygame-ce` or native OS fallbacks.
- **Non-Destructive In-Memory Editing**:
  - **Replace Audio**: Swap out audio payloads while automatically recalculating sizes, offsets, and Wwise codec plugin identifiers.
  - **Add Variations**: Insert extra sound variations into Random/Sequence containers, Switch containers, Actor-Mixers, and Music Segments with automated child table rewriting.
  - **Remove Audio**: Safely decouple sounds without leaving dangling references or corrupted chunk offsets.
- **Wwise Project Template Exporter**: Automatically translates compiled game banks into fully editable XML work units (`.wwu`) and project definitions (`.wproj`), recreating Actor-Mixer Hierarchies, Interactive Music Hierarchies, Events, and SoundBanks.
- **Smart Packager & Binary Patcher**: Ingests new soundbanks generated by the official Wwise Authoring Tool, remaps internal IDs to League short IDs, packages streams into 8-byte aligned `.wpk` packages, and patches music and event soundbanks in place.
- **Pre-Export Integrity Validation**: Built-in verification engine checks for broken cross-references, invalid DIDX table offsets, payload bounds, and orphaned objects prior to disk rebuild.
- **CommunityDragon Live Hash Synchronization**: Automatically fetches and maintains up-to-date name dictionaries for League game hashes, resolving hex IDs (e.g., `0x5F1A84B2`) to readable strings (e.g., `Play_vo_Darius_Q_Attack`).

## Supported Formats & Specifications

| Format | Extension | Description | Role in LAM |
| :--- | :--- | :--- | :--- |
| **Wwise SoundBank** | `.bnk` | Wwise container file with `BKHD`, `HIRC`, `DIDX`, and `DATA` chunks. | Fully parsed; preserves unknown chunks; reconstructs HIRC tree and embedded audio. |
| **Riot Audio Package** | `.wpk` | Riot `r3d2` package holding streamed `.wem` files with 8-byte aligned offsets. | Full unpack, payload extraction, repackaging, and deterministic rebuilding. |
| **PROP Property Bin** | `map.bin` / `.bin` | League client/game binary property files containing string event lists. | Extracted for FNV-1 hash-to-name lookup tables. |
| **Wwise Encoded Media** | `.wem` | Compressed audio payloads (Vorbis, Opus, ADPCM, or PCM RIFF). | Decoded for preview, validated, and injected into banks/packages. |
| **Wwise Work Unit** | `.wwu` / `.wproj` | XML project hierarchy used by Audiokinetic Wwise Authoring. | Generated from parsed banks for external editing and mixing. |

## Prerequisites & Installation

### 1. Requirements
- **Operating System**: Windows 10 / 11 (64-bit recommended)
- **Python**: Version `3.10` or higher
- **Audio Decoder**: Pre-bundled with `vgmstream-cli.exe` and required codecs in the `tools/` folder.

### 2. Setup Environment

Clone the repository and install the required Python dependencies:

```bash
git clone https://github.com/your-username/league-audio-modder.git
cd "league-audio-modder"

# Create a virtual environment (optional but recommended)
python -m venv .venv
.venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
```

> [!NOTE]
> `pygame-ce` (Community Edition) provides high-performance audio streaming. If it is not installed or supported on your environment, LAM automatically falls back to native Windows `winsound`.

## Detailed Workflows

### 1. Inspecting & Previewing Game Audio

1. Click **Import** (or press `Ctrl+O`) and select:
   - The character or map **Events BNK** (e.g., `darius_base_sfx_events.bnk`).
   - The corresponding **Audio WPK** or **Audio BNK** (e.g., `darius_base_sfx_audio.wpk` or `..._audio.bnk`).
   - *(Optional)* The character's `skin#.bin` or `map.bin` file to resolve hash names.
2. The left pane displays the fully reconstructed tree.
3. Click on any **Sound** or **MusicTrack** node:
   - The properties panel displays object ID, WEM ID, parent containers, and bus routing.
   - The bottom-right audio panel loads the sound and enables playback (`Space` / `▶`).

```
└── Event: Play_vo_Darius_Q
    └── Action: Play (Target: 483)
        └── RandomSequenceContainer (ID: 483)
            ├── Sound: [WEM 386105878] "Darius_Q_Cast_01"
            ├── Sound: [WEM 263263092] "Darius_Q_Cast_02"
            └── Sound: [WEM 269810161] "Darius_Q_Cast_03"
```

---

### 2. Replacing Existing Sounds

1. Locate the Sound node you want to modify in the hierarchy.
2. Click **Replace Audio** on the toolbar (or right-click → **Replace Audio**).
3. Select your custom `.wem` file.
   - *If selecting a `.wav` or `.ogg`, LAM will display a compatibility warning explaining that the game requires Wwise-encoded WEMs.*
4. The sound's payload and byte length update in memory, and the node is highlighted with a green indicator.

---

### 3. Adding New Audio Variations

To add a new sound variation to a skill or effect:

1. Select the parent container (e.g., a `RandomSequenceContainer`, `SwitchContainer`, or `BlendContainer`).
2. Click **Add Audio** on the toolbar.
3. Select one or more `.wem` files.
4. LAM will:
   - Read the existing sound objects under that container to use as a structural template.
   - Clone the template's HIRC node, assigning the new WEM ID.
   - Insert the new sound object into the bank.
   - Safely update the parent container's child count and child list table.

---

### 4. Exporting Directly for the Game

1. Once you have completed your modifications, click **Validate** to run the pre-export safety checker.
2. Click **Export Rebuilt** (or press `Ctrl+S`).
3. Choose an output directory.
4. LAM writes out:
   - Clean, rebuilt `.bnk` files with updated DIDX and HIRC chunks.
   - Rebuilt `.wpk` packages with correct 8-byte aligned offset tables.
5. Deploy these files to your League mod manager (e.g., cslol-manager).

---

### 5. Exporting to Wwise Authoring Tool (`.wproj`)

LAM can reverse-engineer compiled soundbanks back into a native Wwise project for advanced sound design:

1. Load your game asset files into LAM.
2. Click **Export Wwise** (or press `Ctrl+Shift+E`).
3. Select a clean Wwise project folder (containing a standard template structure).
4. LAM automatically generates:
   - `Actor-Mixer Hierarchy/Default Work Unit.wwu` (Containers, Blend Trees, Sounds).
   - `Events/Default Work Unit.wwu` (All play, stop, and switch actions mapped to their original targets).
   - `Interactive Music Hierarchy/` (Segments, Tracks, Playlists).
   - Bus and Conversion Settings linkages.
5. Open the project in the **Audiokinetic Wwise Authoring Tool** to edit volumes, curves, attenuation, or apply DSP effects.

---

### 6. Smart Packaging & BNK Patching

When generating soundbanks from Wwise, the authoring tool changes internal object IDs and separates files. LAM's **Smart Packager** bridges this gap:

1. Build your soundbanks in Wwise Authoring.
2. In LAM, click **Package WPK / Smart Packager**.
3. Select your Wwise output directory (where `SoundbanksInfo.xml` and generated `.wem`/`.bnk` files reside).
4. Select the export destination.
5. The Smart Packager will:
   - Parse `SoundbanksInfo.xml` to associate Wwise internal IDs with the original numeric League WEM IDs.
   - Repackage streaming files into an 8-byte aligned `.wpk` archive.
   - Run `BnkPatcher` on generated event banks to align MusicTrack IDs and header versions with game expectations.

## Under the Hood: Technical Architecture

### HIRC Object System

Wwise soundbanks store object definitions inside the `HIRC` chunk. LAM implements deep binary serialization for all major HIRC object classes:

```
┌──────────────────────────────────────────────────────────┐
│                   Wwise HIRC Types                       │
├──────────────────────────┬───────────────────────────────┤
│ 0x01 Settings            │ 0x0C MusicSwitchContainer     │
│ 0x02 Sound (SFX/Voice)   │ 0x03 Action                   │
│ 0x04 Event               │ 0x05 RandomSequenceContainer  │
│ 0x06 SwitchContainer     │ 0x07 ActorMixer               │
│ 0x08 AudioBus            │ 0x09 BlendContainer           │
│ 0x0A MusicSegment        │ 0x0B MusicTrack               │
│ 0x0D MusicPlaylist       │ 0x0E Attenuation              │
└──────────────────────────┴───────────────────────────────┘
```

LAM preserves raw binary payloads for every object. When modifications are made, only the specific offsets (such as child counts, media sizes, or plugin IDs) are spliced in-place, preventing corruption of undocumented or game-specific fields.

---

### Wwise FNV-1 & Mixed-Endian GUID Hashing

Wwise uses two primary hashing strategies to identify resources:

1. **FNV-1 32-Bit Hash** (used for SoundBanks, Events, and Game Syncs):
   ```text
   hash = (OffsetBasis * Prime) % (2^32)
   ```
   *Normalized to lowercase, forward-slashes, and stripped of whitespace before hashing.*

2. **Mixed-Endian 30-Bit GUID Hash** (used for Sound SFX, Audio Buses, and WEM ShortIDs):
   - Parses standard GUID `{XXXXXXXX-XXXX-XXXX-XXXX-XXXXXXXXXXXX}`.
   - Reorders `Data1` (4B LE), `Data2` (2B LE), and `Data3` (2B LE) into big-endian byte sequences while preserving `Data4` (8B BE).
   - Computes FNV-1 over the 16-byte reordered structure, masked to 30 bits:
     ```text
     hash = FNV1_32(reordered_bytes) & 0x3FFFFFFF
     ```

---

### Codec Detection & Plugin ID Patching

When audio is replaced or added, LAM inspects the RIFF header to identify the audio codec and automatically patches the Sound object's 4-byte `plugin_id`:

- **Wwise Vorbis** (`fmt = 0xFFFF`): `0x00040001`
- **Wwise Opus** (`fmt = 0x0302`): `0x00060001`
- **Wwise ADPCM** (`fmt = 0x0002`): `0x00020002`
- **PCM WAV** (`fmt = 0x0001` / `0xFFFE`): `0x00010001`

---

### CommunityDragon Live Hash Sync

LAM integrates with the **CommunityDragon** open-source data repository:
- On startup, a background thread queries GitHub for the latest ETags on League hash lists (`hashes.game.txt.*`, `hashes.binentries.txt`, etc.).
- If updates are detected, it downloads the incremental diffs and updates local cache files inside `hashes/`.
- Fast, lock-free lookups allow hundreds of thousands of hashes to resolve instantaneously in the UI without freezing the main thread.

## Headless Scripting & API

All core modules (`lam.model`, `lam.engine`, `lam.parsers`) are fully decoupled from Tkinter. You can script automated sound replacement and package rebuilding directly in Python:

```python
from lam.model.project import Project
from lam.engine.modifier import Modifier
from lam.engine.rebuilder import Rebuilder

# 1. Initialize project and load assets
project = Project()
project.auto_load([
    "darius_base_sfx_events.bnk",
    "darius_base_sfx_audio.wpk",
    "skin0.bin"
])

# 2. Modify audio payloads
modifier = Modifier(project)
# Replace sound variation 386105878 with custom WEM
modifier.replace_audio(386105878, "custom_sound.wem")

# 3. Deterministically rebuild and export
rebuilder = Rebuilder(project)
outputs = rebuilder.rebuild_all("output_directory")
print(f"Exported: {outputs}")
```

## Troubleshooting & FAQs

#### "Why does my replaced sound fail to play or crash bnk-gui?"
Ensure that you are importing **Wwise-encoded `.wem` files**, rather than standard raw `.wav` or `.ogg` files. The League game runtime requires specific Wwise codec framing (such as Wwise Vorbis with codebook metadata or Wwise Opus). Use the official Wwise Authoring Tool or `wwiser` to encode your WAV files into WEM before replacing.

#### "The tree shows '0x1A2B3C4D' instead of a human-readable event name."
This means the event hash was not present in the local CDragon database. Make sure your internet connection allows the background hash updater to complete, or import the champion's `skin#.bin` file to extract localized string mappings directly.

#### "Can I run this without a GUI?"
Yes. All core subsystems (`lam.parsers`, `lam.engine`, `lam.model`) are decoupled from Tkinter. You can script batch replacements or exports via Python scripts (refer to the [Headless Scripting & API](#headless-scripting--api) section above for an example).
